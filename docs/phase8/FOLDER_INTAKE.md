# Folder intake candidate — review before merge

The person folder controls use native `intake.ingest` with the folder reference
kind and an internal adapter. A plain agent `ingest("folder:...")` cannot grant
an external read: it is quarantined before the folder is opened. Disabled Geo
remains a no-op; enabled use keeps the shared survey and pinned 0.2.0 CLI.

Capture records a generated, content-addressed metadata inventory; card facts
reference a per-folder evidence record. Both have DIK records. Source bodies
remain **not examined**. Unchanged inventory evidence is reused; changed evidence
or failed integrity checks invalidate acceptance independently of the native
survey fingerprint cross-check. The survey is metadata based: same-size edits
with restored timestamps are outside its detection guarantee. Reading/indexing
later has its separate byte/hash checks. Credential paths are names-only refusals;
generated bundles and graphify outputs never become folder-content facts.

Descriptions pass the shared provenance arithmetic check before display and
acceptance. Contradictions refuse; unsupported quantities remain labelled, and
this does not verify behavioral claims or source truth. Duplicate inventory
matching reuses `document_identity`: matches are explicitly metadata candidates,
never verified body duplicates, and nothing is merged, moved or deleted.

Production card drafting is **disabled**, including when spend is checked. Only
scripted endpoints run in free tests. Their two tasks are description and
sensitivity, over metadata only. Enabling a real route needs owner qualification
approval and a bounded estimate first; no such approval or activation is implied
by this candidate. `review_required` cards require individual person review.

Select an exact bounded set of unambiguous cards and approve for processing.
Then use Staging's existing person-started approved batch. It reuses the run log,
Core writer, per-item progress, cancellation, stage keys and stale-input guards.
Model stage keys include the route. Queued drafting remains partial; processing
never accepts a folder or claims the source was read. Acceptance remains an
explicit person action; it sets authorship/content roots and records acceptance
evidence plus DIK. Failed graph application retains its conservative read barrier.

For an already-approved source processing batch, a verified full paper conversion
is now published automatically into its deepest accepted current folder graph.
Unreviewed/failed/excluded assignments cannot publish. The installed Geo CLI checks
artifact hashes, provenance, original source scope and exclusions, creates a fresh
paper generation and compares catalog state before binding it. Old generations
and original files remain intact. Catalogue-only sources remain catalogue-only.
Failed unbound candidates are retained for inspection; no automatic deletion.

No model binding, live library, live paper catalog or personal expectation pack
is changed by these free candidate checks. The final S6 fixture and complete
native/Geo suites must be reported before separate combined Wave L+B0 approvals.
