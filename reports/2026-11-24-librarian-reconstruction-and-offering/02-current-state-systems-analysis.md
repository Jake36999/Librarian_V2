## 2. Eight-Dimension Systems Analysis of the Running System

### 2.1 Process Boundaries, Parent/Child Relationships & Hand-Offs
- **No single-call "ingest -> catalogued" pipeline:** As `DOC-V1D-30` established and `intake.py:545-670` + `tools/staging.py:544-760` confirm, V2 deliberately breaks lifecycle progression across **three separate invocation boundaries** and **two approval gates**:
  1. *Ingestion Entry (`tools/intake.py` -> `intake.py:545`)*: Triggered either directly (`ingest(ref, brief)`), via sessionless/framed queue drain (`intake_run`, `standard/workflows/run-queue.yaml`), or internally by folder intake (`intake._ingest_folder`, `ref="folder:..."`, internal `FolderReview` only, `:553-556`). Outputs `.librarian/staging/` records — **never writes `Sources/`**. Within an open session (`_attach`, `tools/intake.py:15-35`), `ingest` and `intake_run` append an **undecided** `candidate` + `library_item` to the Session JSONL (`rejected` immediately only if `screened_out`).
  2. *Gate 1 — Approve for Batch (`staging_decide(..., "approve")` or UI)*: Only `source` items not carrying `revision_of` can be approved (`staging.py:966`). Note that **folder cards** enter staging via `FolderReview` and get approved/accepted via `FolderReview.accept` / `accept_by_policy` (`folder_review.py:570-750`) — and also receive `FOLDER_STAGES` entries processed inside `process_approved` (`batch.py:801`).
  3. *Approved Batch Child (`tools/batch.py:9` -> `batch.start:672` -> `batch._run:784`)*: Single process-guarded worker (`_LIVE[vault.root]`, `threading.Lock` `_GUARD`, serial per-vault, supports `background=True` thread). Freezes `waiting(vault)` (`status=='approved'` across both `'source'` and `'folder'`!). Runs **without a session** (`worker_ctx = Context(tier=ctx.tier, vault=vault, ...)` — `batch.py:706`) holding an explicit `workflow_grant` for `STAGE_TOOLS` (`Ask` prompts bypassed for those declared batch stage writes). It never promotes notes to `Sources/`.
  4. *Gate 2 — Accept & Promote (`tools/staging.py:544` -> `staging.decide` -> `promote.py`)*: Only after batch completion (or direct `Accept as captured` skipping batch enrichment!) does `staging_decide("accept")` invoke `PromotionGuard` + six-step `promote`, returning accepted `handoff` undecided candidates to originating sessions (`tools/staging.py:737-747`).
- **Session Phase State Machine (`standard/phases.yaml:1-353`, `session.py`):** Data-driven table across `8` purposes (`add_project`, `explore`, `suggest`, `apply`, `start_pursuit`, `learn`, `add_capability`, `audited`). Note a structural seam (`DOC-V1D-31`): `ingest` and `queue_source` sit inside `ingest`/`search`/`seed`/`assess` bundles (`phases.yaml:77,110,192,264`), whereas `intake_run`, `deep_read`, `run_workflow`, `run_pipeline` are unlisted in `session.WRITES` and `process_approved` (`scope="library"`, `tier="curate"`) sits outside session phases altogether (`tools/batch.py:9`).

- **Lineage & Identity Chains Verified in Code:**

### 2.5 Data Management: Single-Ingestion-Pathway Consolidation & Evidence-Derived Medallion / DIK Architecture
This dimension answers a core question of the reconstruction: *how did V2 consolidate Librarian's data management into one ingestion pathway, and how do Medallion layering and project quality expectations map onto it?*

1. **Why & How V2 Consolidated Fragmented V1 Ingestion (`DOC-V1D-12`, `DOC-V1D-20`, `DOC-V1D-30`, `DOC-POL-14`):**
   - V1 scattered ingestion across `build_solutions_library.py` (`4,650` LOC bypassing airlocks and clobbering manual prose, `DOC-V1D-02`, `DOC-V1D-09`), `scout/` (`populate`), `intake`, `papers`, `enrich`, and standalone `lens.py`.
   - V2 consolidated *all* source acquisition (`GitHub`, `arXiv`, `DOI`, `web page`, `dataset`, `local Inbox file`, `folder:<path>`) into **one `intake.ingest` + `StagingStore` airlock**, followed by **one resumable batch engine (`batch.py`)** and **one guarded promoter (`promote.py`)**, while replacing V1's automatic migration scripts with read-only staged V1 export (`v1_export.py`, `DOC-POL-15`).
   - Crucially, **consolidation means one governed airlock & state lifecycle, NOT skipping intermediate grading stages**: `ingest` performs cheap Bronze capture + Silver preview drafting (`describe`), `process_approved` performs full Silver deep reading/conversion/DIK/Geo publication, and `promote` finalizes findable Silver catalog notes so sessions can build Gold synthesis (`DOC-V1D-30`).

2. **Evidence-Derived Medallion & DIK Architecture (`DOC-V1D-05`, `DOC-V1D-08`, `DOC-V1D-39`, `DOC-V1D-40`, `DOC-V1D-44`, `DOC-POL-06`):**
   Deriving directly from project specifications (`Data Information Knowledge` `DOC-V1D-05` + agnostic Medallion definition in `DOC-V1D-08` + `access-model.md` `DOC-POL-06`), Librarian's layers obey a **strict replay-from-prior-grade invariant**:

   | Medallion Grade | Librarian DIK Equivalent | Physical V2 Stores & Modules | Epistemic Rule & Permitted Assertions | Replay / Promotion Transition |
   |---|---|---|---|---|
   | **Bronze (Raw Data)** | **Data** (+ *Semantics* in Owner's 3-level model `DOC-V1D-06`) | `.evidence/` (`evidence.py`), `.librarian/quarantine/`, `.librarian/intake_queue` / `status='queued'`, `folder-surveys.json`, `.librarian/derived/dik/` raw component/chapter facts | Immutable captured bytes, file listings, SHAs, `github_license_spdx`. Asserts *only* what was physically fetched/observed at a commit/date. Never edited in place; errors quarantined explicitly. | Mechanical extraction (`text.extract`, `deploy_survey`, `facts.derive_axes`) produces immutable Bronze records. |
   | **Silver (Curated Information)** | **Information** (+ *Semiotics*, relating Data points *without project framing*) | `.librarian/conversions/<id>.md` (`paper_graph.py`), `.librarian/staging/` (`staging.py`), promoted `Sources/<kind>/<name>.md` & `Concepts/` (`promote.py`), rebuildable `.librarian/index.sqlite`, `Indexes/`, `.nodes.json`, Geo SQLite DBs | **Must remain unframed (`DATA_IS_UNFRAMED`, `unframed()`, `workflows.py:766`)** and grounded in Bronze evidence (`clerk.grounded`, `provenance.check_sections`). Reproducible by replaying from Bronze + conversions. Third-party text stays behind conversion/S1-S6b scope (`DOC-POL-06/08`). | Guarded two-gate transitions: `ingest` -> `batch` -> `staging_decide('accept')` -> `PromotionGuard` + `index.upsert` + `findability`. |
   | **Gold (Framed Knowledge)** | **Knowledge** (+ *Pragmatics*, tested against need/use) | `.librarian/sessions/*.jsonl` (`Session`, `Brief`, `Candidate`, `decision`), verified `Offerings/` (`offerings.py`), `Applications/` (`precedent`) | Framed by a specific project, need, disqualifiers, and perspective/lenses. Every Offering claim requires `EVIDENCE_QUOTE_VERIFIED`; real runtime truth lives in `Applications/` ("what it actually did", `DOC-V1D-05`). | Created in `judge -> synthesise -> check_out` (`phases.yaml`) from Silver notes; Application `unresolved_sources` should feed back to Bronze queue. |

   **Critical Disambiguation (`DOC-POL-02`, `DOC-POL-09`):** V2 also uses `gold`, `silver`, and `bronze` for **Trust Tiers** on Geo-Grapher graphs and W5 checked relations (`third-party` code = `bronze` trust tier). Storage Medallion layers (`Bronze/Data -> Silver/Info -> Gold/Knowledge`) measure *refinement & framing*; Trust Tiers measure *epistemic verification strength*. Conflating them (`G4`) misclassifies immutable Bronze evidence as "low quality" or `bronze` third-party code graphs as "unparsed raw bytes".

### 2.6 Validation, Quality Gates, Acceptance & Publication
- **Implemented Validation Chain:**
  1. *Ingest & Arithmetic:* `quality.py` detects `needs_ocr` (`empty_pages/n >= 0.3`), `cleanup` (broken hyphenation `>3%` / headers / page numbers), `js_shell` (`<400` chars beside `>=3` scripts); `provenance.py:30-87` verifies numbers in repository/folder descriptions against evidence caps (`CAPS = {modules: 80, endpoints: 60, entry points: 40}`, skipping qualified subset phrases `QUALIFIED`).
  2. *Deep Read & Lens Grounding:* `deep_read.py:256-368` binds part reuse to SHA-256 of `{chunker, chunk_chars, representation, recipe, c.text}` (`CHUNKER = "paragraph-pack/1"`), resetting count-only legacy records as `STALE_LEGACY`; blind `challenge` step (`:457-470`) + `topic_not_stance` E4 check (`:490`) + `screen_instruction` E5 injection check (`:512`) guard lens proposals; `_document_pass` requires `len(chunks)` read and 2+ verbatim parts (`:849`).
  3. *Review & Readiness:* `batch._review:382-414` retries `not_confident` once, rescues grounded drafts as `low_confidence`, and demotes to `partial` if `seen["read"] < seen["chunks"]`; `_metadata` reports Content Model readiness (`UNFILED` default topic if vault has <=1 topic).
  4. *Promotion & Publication:* `PromotionGuard` validates SHA-256 fingerprints across up to `200` observed/target paths, checks Obsidian dirty leases, streams copies with before/after digest checks (`promote.py:483-511`), runs Note Content Model check (`index.model.check`), and marks `needs_attention` if `findability()` fails. `paper_graph.publish_artifact:163-197` requires `full_conversion`, non-excluded trusted accepted folder card (`person` or `agent-policy` in `promotion.mode='agent'`), clean `review.validate(card)`, and exact `.nodes.json` SHA-256.
  5. *Offerings:* `EVIDENCE_QUOTE_VERIFIED` requires contiguous substring match against stored source text (`DOC-V2E-02`, `phases.yaml:127`).
- **Remaining Validation Weaknesses Verified in Code (`d9435e1`):**
  - *Part-count completion masks derived gaps (`batch.py:368-370`):* `_read` returns `"complete"` as soon as `not out.get("remaining")` (chunk count == read), even if `_document_pass` was skipped (`first.ok` false or refused — `_document_pass:823` returns `"done": True` even when `not first.ok`!) or `relate_chapters` returned `added: 0` due to Clerk failure (`dik.py:397`).
  - *Stage keys omit model/prompt recipe details inside non-`read` stages:* While `batch._run:790,809` hashes `_source_identity` + `_route_identity`, a changed PDF cleanup/OCR prompt version or partial upstream parse does not invalidate independently unless upstream was inside `dependencies` (`batch.py:812`).
  - *Raw filename titles & `Unfiled` default (`W8`, `intake.py:653` + `DOC-MAP-13`):* Vaults with only `Unfiled` skip Clerk topic selection (`len(topics) > 1` at `intake.py:734`), leaving all `363` RL Sources with 0 topics beyond `Unfiled` unless `topic_propose` + person acceptance runs.
  - *Staging pager bug (`F-01`, `DOC-RPT-10`):* `registry.py:MAX_LIMIT=50` silently truncates `staging_list(limit=100)` (`Show 50 more` in UI fails to paginate past 50 of `55` RL partial sources or `1,664` RL staged folders!).

### 2.7 Error Handling, Retries, Escalation, Recovery & Unresolved Failures
- **Quarantine & Intake Retry:** Capture/fetch errors go to `.librarian/quarantine/intake/<hash>.json` and create retryable `status='failed'` items in staging (`tools/intake.py:70-75`, `queue_retry`); rejected items go to `.librarian/quarantine/` with original files retained.
- **Batch Fault Containment & Interruption:** Uncaught stage exceptions fail *only that item* (`batch.py:841-860`), preserving sibling items and prior completed stage receipts (`done`); concurrent file changes invalidate completion as `status='stale'` (`:851`); `batch_cancel` checks between stages (`:829`); `usage_log.budget` stops only **before starting each next item** (`:795`) — *NOT* reserving atomic budgets before inner Clerk/OCR/PDF calls (`MC-10` gap!).
- **Workflow Runner Recovery & Ask-Mode Security Holes (`F-02`, `F-03`, `DOC-RPT-10`):** `workflows.py:1066-1099` persists `dispatch` before tool execution and pauses on `outcome_unknown` unless safe-read/idempotent, showing declared `compensation` without auto-running it (`:593-605`, `:1001`, matching `composition.md` Rule 8). However, **two verified security/correctness defects remain unaddressed in Stress Findings `DOC-RPT-10`:** `F-02` (macro checkpoint approval reuse across sessions/cancelled cards & concurrent race) and `F-03` (accepted vault pipelines silently auto-grant `contribute` writes in Ask mode without UI disclosure).
