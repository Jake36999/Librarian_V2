## 3. Formalised Reconstruction Methodology (`RRM-7`) — Ready for Phase 2 Geo-Grapher Reapplication

To avoid repeating `G1–G6`, both this Librarian reconstruction and the upcoming Phase 2 Geo-Grapher reconstruction must execute the following **7-Step Records-Based Reconstruction Methodology (`RRM-7`)** in strict order:

1. **Scope & Provenance Mapping (No Silent Omissions):** Enumerate all primary development archives, policy roots, code checkouts, deployed mirrors, and graph catalogs before analysis. Record explicit access gaps (e.g. `E:\DataManagement` empty, partial mirrors, excluded/withdrawn folders) so missing files are never misclassified as decisions against a design.
2. **Primary Index & Terminological Disambiguation:** Assign every inspected record a stable identifier (`DOC-*`), file anchor, document kind, Rank (`1–7`), and initial acceptance evidence. Resolve homonyms and V1→V2 term shifts in a controlled Glossary before synthesizing findings.
3. **Read-Only Multi-Surface Evidence Slicing:** Extract three independent empirical views of the live system at a pinned commit (`d9435e1`):
   - *(a) Static AST & State-Machine Extraction* (entry points, stage sequences, constants, refusal codes, persisted JSONL/SQLite schemas);
   - *(b) Graph Catalog & Entity Verification* (`list_graphs` -> filtered `search_entities` -> verbatim `entity_id`/`cite_as`/`identity_scope` -> `get_entity_content`/`find_dependants`, checking filter/index behavior critically);
   - *(c) Runtime Operational Telemetry* (`G:\Libraries` logs, staging/queue/budget states, live Core API `/api/meta`).
4. **Conflict Resolution via Authority Precedence (`DOC-POL-01`):** Whenever specs, old audits, diagrams, and code disagree, explicitly document both accounts and resolve by `DOC-POL-01` Ranks `1–7`, keeping implementation truth (`src/`) distinct from accepted targets (Rank `3`) and proposals (Rank `5`).
5. **Six-Category Epistemic Ledger & Medallion/Boundary Tracing:** Classify every material capability and safeguard into `IMPLEMENTED_VERIFIED`, `ACCEPTED_UNIMPLEMENTED`, `PROPOSED_UNACCEPTED`, `UNIMPLEMENTED_UNDROPPED` (explicitly preserving non-rejected absences), `DECIDED_AGAINST`, and `UNRESOLVED_CONFLICTING`. Trace data storage transitions explicitly across Medallion layers (`Data/Bronze` -> `Information/Silver` -> `Knowledge/Gold`) and service boundaries.
6. **Non-Regressive To-Be Synthesis Before Visualisation:** Construct target architecture changes **only after Steps 1–5 complete**, auditing every proposed transition against `R1–R6` regressions (ownership, gating, reservation, whole-source truth, policy-compliant recovery, boundary contracts) and tying each recommendation (`REC-*`) to `DOC-*` and code evidence.
7. **Policy-Checked Specification & Pure-Model Diagramming:** Author `.spec.yaml` behavioral models free of visual-routing clone artifacts (`*_at_<hash>`), cross-check every `ref` outcome contract and Rank-1 policy rule (`Rule 8` no auto-rollback, `Rules 15–17` permission envelopes), and validate canvas geometry separately (`render_spec.py` + `canvas.service` + PNG preview checks).
