## Corrections (max four)

**1. R1's "shared classification" fix is under-specified and risks a bad classification suggestion.** The consolidated plan says to "share classification between index, validation and status" and to "distinguish foreign docs from managed notes without relying solely on folder/frontmatter presence." The fact check itself concedes folder placement cannot distinguish an adopted doc from a managed note that lost metadata, and that `schema.ContentModel.shape_of` (`src/resource_librarian/schema.py`) returns `""` for unshaped notes — it never returns `workspace_document`. The plan correctly rejects the one-line `shape_of(...) == 'workspace_document'` replacement, but then proposes a shared classifier without naming its authority. Correction: state explicitly that the classifier must be driven by an explicit managed-identity/provenance signal (or user-declared policy), not by folder or frontmatter heuristics, and that `check_notes` (`src/resource_librarian/tools/core.py`) must not silently skip plain docs from link collection. The current `continue` at the `workspace and not note.frontmatter` branch drops those docs from `names`/`links`, which is what produces the false orphan; the fix must collect links before the skip, not after.

**2. R3's "never refund uncertain billable requests automatically" is correct, but the plan's surrounding language overclaims what the G5 runner proves.** The plan says the "pre-call estimate guard and locked shared run ledger added" and asks to "show that each billable dispatch, including retries, has an adequate reservation." In `scripts/g5_measure.py`, `guard()` wraps `loop._reserve_profile_budget` and uses `PROMPT_MARGIN = 4.0` on a `chars/4` estimate — a heuristic, not a demonstrated bound on serialized provider requests. `Meter` only records usage from `trace_sink` rows; `without_usage` stops the run but does not reserve. `Ledger.record` writes spend *after* a task, so a crash mid-task leaves no durable per-call reservation. Correction: the plan should say the guard is a pre-dispatch heuristic that fails closed on missing usage, and that durable per-call reservation/settlement is *not yet implemented* in the G5 runner — not that it "has" it. Do not claim the estimate "bounds the real cost"; the comment in `PROMPT_MARGIN` asserts a provider cannot bill more input tokens than characters sent, which is an assumption about tokenization, not a verified bound.

**3. R5's "the latter meets the recorded measurement rule on its declared task mix, despite zero fully completed sessions" is an overclaim of test evidence.** The fact check's own G5 section says "No session completed with all requirements closed" and "that does not qualify general coding capability, high task-success rate, budgets under crashes or semantic correctness." The consolidated plan then says the 25/74 run "meets the recorded measurement rule" and may be "reuse[d] for unchanged tested behavior." Correction: separate the *measurement rule* (a permissive Tier A share threshold) from *qualification*. The plan should state that 25/74 satisfies the predeclared counting rule only, that zero fully-closed sessions means no end-to-end success was demonstrated, and that reuse is limited to unchanged admission/closure/accounting behavior — not to claims about capability, budget safety under crash, or semantic correctness. Also note the fact check's own caveat that "a final clean independent suite was not established before the run," so the run's baseline is unqualified.

**4. R1's aggregate-search fix overreaches on filter semantics; the plan should not imply source-axis filters are a general contract.** The fact check confirms `_everything` (`src/resource_librarian/search.py`) copies `verdict`, `coverage`, `considered`, `facets`, `constraints`, `tier_reached`, `removed_by_filters` from `orient` only, and that `source`/`max_age_days` are forwarded only to `orient`. The plan's R1 says to "expose per-group considered/matched/verdict/filter applicability" and "reject or explain unsupported parameter combinations rather than silently treating a source selector as universal scope" — good. But it also says "Source-license/age filters do not automatically make sense for every other shape," which is correct, yet the plan's earlier framing ("Fix aggregate search's response contract") risks implying the fix is a contract change to `search()`. Correction: scope the fix to `_everything`'s envelope assembly (per-group metadata, honest aggregate verdict, explicit `ran`/filter-applicability reporting) and to `search()`'s `Constraints.of` rejection path for inapplicable axes — not to redefining `source`/`max_age_days` semantics for `pattern`/`made`/`workspace`, which the fact check says "much of this predates DEPLOY-03" and which the plan should leave as documented exclusions rather than silently extend.
