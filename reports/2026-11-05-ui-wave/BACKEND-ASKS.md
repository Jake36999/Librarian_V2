# Core requests for the UI wave

1. Revision-check ordinary source approve and defer. In src/resource_librarian/tools/staging.py, staging_show issues staged_revision, but _decision_intent returns early for these two decisions and staging_decide only explicitly redeems the token for model expectations. A second tab can change an ordinary source between its inspection and the write. Support one expected staged revision per item, checked inside the write boundary; return a conflict and leave that item untouched on mismatch. The UI can then submit independently and report each result. Until then lightweight bulk triage is absent.
2. Provide safe identity for recovery of a macro from a historical result. The outcome_unknown response carries the interrupted tool, its arguments and completed count. It does not supply the original checkpoint_id and bound macro inputs. The live stream emits tool arguments on a separate event without a call identifier on the result. A Core-issued recovery handle or a durable checkpoint lookup binding the original inputs to the paused dispatch would enable explicit retry/applied buttons, including after reconnect. Current UI shows the Core guidance.
