# UI wave verification

Tested against a disposable library. The development browser checks ran with the demo Core. The installed test used an exact wheel in a fresh external virtual environment and kept Edge connected while the packaged Cowork command enumerated 148 tools. Core protocol 2, package version 2.1.0.dev0.

## Observed task paths

| Task | Observation |
|---|---|
| Find Settings while reviewing | Fresh installed browser clicked Staging, opened Settings in the header, reached Health and read the first successful Core snapshot. Escape returned to the app. |
| Follow a missing-reviewer warning | Browser smoke injected the queued-draft field on a real staged source and followed Configure reviewer model to its named role. This exercises discovery up to the picker; no paid reviewer job was run. A library with missing earlier roles must still configure those first. |
| Distinguish processing from publishing | The captured item describes both next states beside the draft. The development walk exercises decisions and their outcomes. Human comprehension has not been measured. |
| Locate evidence | The browser opened a staged item and its evidence, ran deep read on the disposable fixture, and checked returned progress. The reader pane remained independently navigable. |
| Distinguish pane views from note actions | The browser opened a linked note, browsed folders, pinned a desk item, opened the agenda, returned to Plan, then used Note actions to rename and restore the fixture note. |
| Recover a failed adapter mount | Node executed the distributed Obsidian view with host, Core and mount doubles. It exercised ordinary retry, typed stale-lease takeover, protocol rejection/retry, mount disposal and heartbeat cleanup. Native hotkey routing and simultaneous real Obsidian use remain a host acceptance task. |

## Layout and artifacts

Development smoke checked 1100, 760, 420 and 320px roots inside a 1440px window. A first pass exposed header overflow at 760px; wrapping the persistent actions fixed it. Packaged smoke checked the search filter row, narrow-root overflow and scoped DOM classes. Installed JS and CSS were compared byte for byte to the checkout bundle. Obsidian adapter contract suite passed all ten tests.

Calculated standalone palette contrast (light / dark) for the new surfaces: muted body text on recessed surfaces 5.25 / 5.06, normal text on secondary buttons 16.47 / 13.25, button border against its fill 3.96 / 4.25. These use sRGB relative luminance. Theme-supplied Obsidian colours require native checking.
