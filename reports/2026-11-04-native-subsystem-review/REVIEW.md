## What the current pipeline actually guarantees

Intake captures source evidence, computes deterministic metadata, sends unframed description tasks to Clerk, and creates staged material. Quality selects extraction/cleanup/OCR branches. Deep-read extracts claims, limits, terms and lenses with located quotations. Extract materialization is bounded and pins repository evidence; it is not an execution facility. Staging acceptance prepares target/dependency fingerprints; promotion writes through the guarded Core path and updates derived indexes. Taxonomy changes are explicitly accepted and planned; upkeep reports drift rather than editing notes automatically. See [staging safety](../../docs/staging-write-safety.md), [extract.py:111](../../src/resource_librarian/extract.py:111), [taxonomy.py:262](../../src/resource_librarian/taxonomy.py:262), and [rules.py](../../src/resource_librarian/rules.py).

Preserve these boundaries. “Accepted”, “quoted accurately”, “arithmetic agrees”, “source says”, and “replicated under this environment” are different predicates. A project shift changes applicability, not the historical fact that a source once made a claim. Store both rather than rewriting source description to fit the new goal.

## Roles and native configuration

Scout discovers/ranks candidates and feeds the same intake pipeline ([scout.py:431](../../src/resource_librarian/scout.py:431)); it is not a separate autonomous Manager. Clerk describes evidence, Scribe composes from a closed brief, and Broker decides action permission. Core's background profile wrapper already provides role/route qualification and rate-card policy. Therefore the gap is correlated accounting and recovery across surfaces, not a wholesale absence of routing or a reason to give Clerk the Manager's conversation. The Cowork [Clerk agent](../../plugin/agents/clerk.md) is a waiting-task adapter; its prompt restriction is useful but not a mechanically enforced fresh context for each successive task.

Keep runtime metadata outside model payloads: parent session, task ID, attempt, evidence digest, profile/route revision, reservation, deadline and cancellation generation. Charge repair attempts and queued fallback submissions to that task. `effort.py` controls ceilings, not authority or proof that every inner model invocation consumes the same reservation. Preserve fixed-role payload tests and add accounting parity tests.

Reply review is advisory, not a hard veto. Keep that behavior. Add reply/turn identity, exact document locator and source revision, checked-span coverage, and challenge status. Insufficient coverage means unchecked, not contradicted. Deduplicate and cap challenges by count and tokens within the same projection budget as other context; retain details by handle. A late review of an older turn must not overwrite a newer challenge set or revive superseded evidence.

Reviewed native YAML definitions include enrichment, deep-read, staged review, cited-source ingestion, weekly review and sync-vault; the latter contains external push effects and must never become automatically replayable merely because it is YAML. Cowork skills provide conversational guidance to registered tools, not executable authority. Existing lens packs distinguish authored methods from source-extracted quotations; preserve that provenance class. `lens_gold.py` already checks per-chunk digests—reuse this principle for deep-read and batch progress. `packs.py` remains a first-party feature boundary, not a new orchestration plugin system.
