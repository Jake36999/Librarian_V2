## New design implications (max 3)

1. **Bound the model's working set explicitly, as remaining_12 does with a top-5 candidate list (p. 22, "5 APIs are Best"):** a harness should pass a retrieved, size-capped evidence set per step rather than an unbounded transcript, and record the cap as a testable parameter.
2. **Translate structured state into text before the model sees it, and keep the raw structure for the verifier (remaining_12, p. 9):** deterministic checks should run on the structured record, not on the model's prose, so a passing check never implies the prose is semantically right.
3. **Treat human correction as a measured cost, not a guarantee (remaining_12, p. 11: 17.6% corrected, ~75% minor):** checkpoint design should budget reviewer time per artifact and log corrections as data, while remaining_09's slow/fast split (p. 5) suggests separating infrequent human-gated decisions from frequent automated steps.

**Risks / assumptions:** All page numbers are from the packet's PDF page markers. remaining_09 and remaining_10 are robotics/control studies; any transfer is analogical and unvalidated for text. remaining_12's gains are benchmark-specific (Java/Web API recommendation) and its explanation quality is human-rated only.
