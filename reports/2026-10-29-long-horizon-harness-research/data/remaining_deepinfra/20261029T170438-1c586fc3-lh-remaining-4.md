### New design implications (max 3)

1. **Treat LLM output as untrusted enrichment with an explicit fallback path.** Source 1's format-check-and-fall-back-to-original pattern (p. 6) is a concrete precedent for a harness that never lets a malformed model response silently become a requirement; the fallback must be logged, not silent.
2. **Bound context by construction, not by hope.** Source 1's proven L̃v ≤ Lmax bound (pp. 9–10) suggests the harness should enforce a hard token ceiling at assembly time and verify it, rather than relying on truncation heuristics.
3. **Separate "pattern" from "proof obligation."** Source 2's pairing of each requirement pattern with a generated lemma set (pp. 1050–1051) is a useful analogy for human checkpoints: each checkpoint should carry its own machine-checkable acceptance condition, with the human supplying only parameter instantiation.
