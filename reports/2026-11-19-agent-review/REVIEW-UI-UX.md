## Lens-by-Lens Analysis (`A1–A9`)

### `A1` — Orientation, First Impressions & Empty/Error States
- **Librarian V2:** Within 30 seconds a newcomer sees a clear chat workspace with three views (`Chat`, `Staging`, `Search`), a session header, and a prompt composer. However, cold load suffers four immediate cracks:
  1. **Pre-hydration blank controls ([librarian-prehydration-blank-pills.png](file:///D:/Librarian_V2/reports/2026-11-19-agent-review/evidence/librarian-prehydration-blank-pills.png), reproduced at `375x812` & `1440x900`):** Before WebSocket/boot hydration completes, the library selector displays generic `"Library ▾"`, the two pills beside `📎` render completely empty ovals, and `Effort` defaults to `4` before snapping to `8`.
  2. **Contradictory empty-state copy:** The empty canvas reads `"Ask the librarian. It opens a session for anything longer than one search, and the plan on the right shows where the thread is"`, yet the right Document Pane (`Show the document pane`) starts **closed** on cold load.
  3. **Broken cold-start documentation & default chat route:** Initial load triggers `GET /api/file?path=About%20the%20Librarian%20and%20how%20to%20use%20it.md -> HTTP 404` on adopted vaults without guide notes, and submitting any chat prompt fails immediately with **`HTTP 404`** (`"The model 'lead-m' does not exist"`) while zero of the 177 DeepInfra models are `qualified` and `DeepSeek-V4-Flash-0731` fails clerk checks (`"experimental (missing)"`).
- **Geo-Grapher:**
  1. **Standalone empty-catalog deadlock ([geo-empty-catalog-deadlock.png](file:///D:/Librarian_V2/reports/2026-11-19-agent-review/evidence/geo-empty-catalog-deadlock.png)):** Launching `geographer serve-graphs --create-catalog --transport http --browse-root ...` with an empty catalog (`GET /api/graphs` returning `[]`) permanently strands the UI at `<main><h1>Geo Grapher</h1><p role="status">Opening project graphs…</p></main>` with **0 buttons** ([Workspace.tsx](file:///F:/uv-data/Geo_Grapher/frontend/src/Workspace.tsx#L181-L190)). A standalone newcomer can never reach `Build -> Add folder…`.
  2. **Librarian-launched Geo dead end ([geo_service.py](file:///D:/Librarian_V2/src/resource_librarian/geo_service.py#L90-L93)):** Because Librarian does not pass `--browse-root`, clicking `Build -> Add folder…` fails with `"No folders are browsable. Start the server with --browse-root DIR."` On ACCEPT-02 (`:65417`), both catalogued DBs are paper-only (`code.sqlite` has only `2` repository entities and `0` fingerprints), showing `"No children in this hierarchy filter"` and causing `Compare` to fail `HTTP 400`.

### `A2` — Label-Only Inferability (`85` Controls Blind-Scored)
- Across 85 controls scored before clicking (see [INFERABILITY-SCORECARD.md](file:///D:/Librarian_V2/reports/2026-11-19-agent-review/INFERABILITY-SCORECARD.md)), surface inferability is strong when interactive (`81/85 = 95.3%` match: Librarian `41/44`, Geo `40/41`).
- The main inferability failures come from **hidden preconditions and missing disabled explanations**:
  - `Librarian`: `Note` tab disabled with `title=null` / `aria-disabled=null`; redundant `Models` button beside `Settings`; `Desk` (`Pin`/`Unpin`) documented in workflows (`Draft weekly pursuit review` mentions `"its desk"`) and present in MCP yet absent from the UI DOM.
  - `Geo`: `Keep only or remove` Scissors icon only appears on the left canvas rail after using `Box select` on canvas (selecting or framing a file via Search or Inspect never reveals it); `Compare` remains clickable on fingerprint-less graphs until it fails `HTTP 400`; `Conceptual Components`, `Validate and activate rules`, `Use the selected item`, `Declare link`, and `Centre` all disable with `title=null` (and `Active` uses `"Shared scene members (at most 3)"` instead of saying `"Already active"`).

### `A3` — Workflow Clarity, Feedback & Mode/Broker Coupling
- **Librarian Ingestion & Batching:** Staging status buckets (`Captured, to review`, `Approved, awaiting ingestion`, `Ingested with gaps`, `Accepted`) communicate pipeline progress clearly, and `Which sources` makes state transitions explicit. However:
  1. There is **no "Add source / URL / path" control inside `Staging`**: the only UI file intake lives under Chat `📎 -> Attach a file from this computer` (uploads to `Inbox/`) or chat/workflow prompts, both broken when the Chat model (`lead-m`) 404s.
  2. Promoting `3788853.3803088` cleanly executed `parse` (`9/9 parts`), then silently stopped at `partial 0/16` (`waiting_on_model: 1`) without surfacing *why* until clicking `Draft with the clerk` revealed `DeepSeek-V4-Flash-0731` is `experimental (missing)` for `clerk`.
  3. Clicking `Accept with partial coverage` on the stale Staging view triggered a self-inflicted **write-conflict checkpoint** (`Checkpoints (1)` — `.librarian/staging/source/3788853-3803088-0dfc42.json changed after it was read`), and reloading erased the previously drafted `Bottom Line` / `What it solves`, forcing manual re-entry.
- **Hidden `Modes: Ask` Broker Trap for MCP Agents:** In default `Ask` mode, calling any write MCP tool (`ingest`, `create_project`, `open_brief`, `desk_pin`) emits an amber `Permission needed` card **only inside the Web UI `Chat` tab** ([librarian-mcp-ask-permission-card.png](file:///D:/Librarian_V2/reports/2026-11-19-agent-review/evidence/librarian-mcp-ask-permission-card.png)). When the user is on `Staging` or `Search` (or has no browser open), there is **zero header badge, counter, or toast**, while the MCP call blocks synchronously up to `600s` (`Broker.timeout`) and exceeds Antigravity's `180s` MCP call timeout without an actionable message.
- **Geo Build Operators (`:64181`):** Once unblocked, `Add folder…`, `Keep only or remove`, `Compare`, `Combine`, and `Declare link` work coherently and keep source graphs immutable. Remaining workflow bugs:
  1. Ingesting multi-part `app_repo` (`3` graphs created via `POST /api/workspace/ingest-execute`) failed to auto-refresh `Graphs (1)` until full page reload (whereas single-part `app_repo_v2` updated live).
  2. `Compare` diff items (`Only in app_repo_v2`, etc.) are static text — clicking an item cannot jump to or inspect it in `3D space`.
  3. After declaring a bridge link, neither clicking the **Gold bridge arc** on canvas nor opening `Inspect -> Links`, `Evidence`, or `List` shows a link card or one-click jump to the target node.
  4. In `Combine`, creating `combined-app` left the previous graph's `Active` button pressed/disabled and caused raw graph IDs (`g_5fb47a54...`) to leak briefly into the `Search` project dropdown.

### `A9` — Agent & MCP Experience
1. **Empty `content: []` in Geo MCP (`v1.30.0`):** `geographer serve-graphs` returns `"content": []` and puts JSON payloads solely in `"structuredContent"`, causing Antigravity `call_mcp_tool` to return blank outputs across all 22 tools (requiring direct stdio JSON-RPC in testing).
2. **Mismatched MCP configs across harnesses:** [~/.claude.json](file:///C:/Users/jakem/.claude.json) points `librarian` at `--vault F:/uv-data/Geo_Grapher` (a code repo, violating `docs/agent-guide.md`) and `geo-grapher` at `Geo_Grapher/output/named-graphs/catalog.sqlite`; Antigravity [librarian/mcp_config.json](file:///C:/Users/jakem/.gemini/config/plugins/librarian/mcp_config.json) points to ACCEPT-02 (contradicting [librarian/rules/AGENTS.md](file:///C:/Users/jakem/.gemini/config/plugins/librarian/rules/AGENTS.md) which names `G:/Libraries/Resource-Library`), while [geo-grapher/mcp_config.json](file:///C:/Users/jakem/.gemini/config/plugins/geo-grapher/mcp_config.json) points to `Resource-Library` (`16` graphs).
3. **Cold `search_entities` latency (`70.96s` / `1.17 GB` RAM):** First search on `Resource-Library-Librarian_V2` (`65,408` entities) took `70.96s` (warm searches `~3.55s`), exceeding common 30–60s MCP client call timeouts.
4. **Schema/description drift causing tool errors:**
   - `search_entities` tells agents to call `get_entity_content(content_kind="documentation")`, which fails at runtime (`Additional properties are not allowed ('content_kind' was unexpected)`).
   - `find_dependants` description instructs `"using the explicit direction and filters"`, yet passing `direction="outgoing"` fails (`Additional properties are not allowed`).
   - `compile_task_packet` fails BOTH with raw canonical `entity:<sha>` (`BRIDGE_ENDPOINT_UNRESOLVED`) and with double-prefixed `entity:entity:<sha>` on test-file hits (`Filter excludes the focus entity`, truncating `'details_handle': Non`).
   - `search_entities` hits omit `file_path` and `kind`, ranking `tests/test_geo_service.py` `external_symbol`s `[0..2]` ahead of `src/` definitions with identical `qualified_name: "GeoService"` — trapping agents into calling `get_architecture_context` and hitting `Filter excludes the focus entity`.
   - `federated_search` omits top-level `entities[]`, nests hits under `result.data.hits`, and returns out-of-order `formal_rank` (`[3, 1, 4, 5, 2]`).
   - `paper_search_documents` uses nested `{graph_id, request}` args (unlike flat code tools) and cites `get_document` instead of `paper_get_document`.
5. **Librarian MCP ergonomics:** `staging_list` returns `"folder"` counts in its summary yet refuses `kind="folder"` (`invalid_arguments`); several descriptions contain broken grammar (`"Use when the Judge phase."`, `"Use when check out..."`); `map` phase allows `advance()` without calling `search(intent="orient")`; and read tools (`desk_show`) consume session `budget_left` silently (`30 -> 29`).
