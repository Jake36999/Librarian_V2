# Source Documentation Standard

A source note is written for someone mid-task who will decide in under a minute whether to open
the source. It owes them five things.

1. **What it is, specifically.** A Bottom Line that could not be swapped onto another note without
   becoming wrong. Generic praise is a failure, however well written.
2. **What is inside, and where.** Code, grammars, datasets, benchmarks, worked examples, with
   paths. A capability nobody located is a capability nobody will find.
3. **What it does without its own field's vocabulary.** Transferable Capability: stated so someone
   in an unrelated field could read it, and saying what it would replace. Never written toward a
   project, including the one that found it.
4. **What was not read.** Anything inferred is marked `**Not read:**` with what was inferred.
   Evidence states how deeply each part was read.
5. **Facts from evidence only.** Every factual field comes from something fetched. `Unknown` is a
   valid value; a plausible guess is not.

A note that passes every schema check can still fail this standard, usually by being generic.
